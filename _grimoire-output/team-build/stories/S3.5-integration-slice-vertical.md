# Story S3.5 — Intégration du slice vertical (phase 3)

**En tant qu'** utilisateur sous Linux, **je veux** lancer « LLM Voice: Speak Document » sur un Markdown et entendre la lecture avec le segment surligné, **afin de** valider la chaîne complète sans GPU (FakeTts en test, provider HTTP réel branché en phase 4).

## Contexte

Sur `main` après merge de S3.1 à S3.4 : `src/net` (EgressGuard), `src/parser`, `src/playback` (pur TS), `src/views/player`, `src/highlight`, `src/ui`, `src/commands` avec `PipelineFacade` et `NotWiredPipeline`. Rien n'est câblé.

## Tâches

1. **Bundling** : `esbuild` en `scripts.compile` (entrée `src/extension.ts`, `--bundle --platform=node --format=cjs --external:vscode --sourcemap`, sortie `out/extension.js`), les dépendances de prod (zod, unified, remark-*) entrent dans le bundle ; `.vscodeignore` exclut `node_modules` ; `npm run package` produit un VSIX qui s'active hors `npm install`. Les tests d'intégration compilent toujours via tsc dans `out/`. L'import dynamique ESM du parser doit fonctionner dans le bundle (esbuild le gère ; vérifier).
2. **DiskAudioCache** (`src/playback/DiskAudioCache.ts`) : implémente `AudioCacheStore` sur `globalStorageUri/cache`, fichiers `<sha256>.wav`, index JSON, éviction LRU à `llmVoice.cache.maxSizeMb`, `put` idempotent, `clearAudioCache` câblé.
3. **Sources** (`src/sources/`) : `MarkdownDocumentSource` (document complet, depuis le curseur, sélection, section courante = heading → heading suivant), `TextSelectionSource` (tout langage), `ClipboardSource` (`vscode.env.clipboard.readText`). Toutes retournent un `SourceDocument`.
4. **Profils** (`src/profiles/`) : `defaults.ts` (les 4 profils du CdC §19, validés par `profile.schema`), `ProfileRepository` : `globalStorageUri/profiles.json` créé au premier lancement, lecture/écriture, JSON Schema généré depuis Zod et enregistré via `contributes.jsonValidation` pour `profiles.json` ; `selectProfile` = Quick Pick ; `openProfiles` ouvre le fichier ; dernier profil dans `globalState`.
5. **Providers minimaux pour ce slice** : `src/tts/FakeLocalTtsProvider.ts` N'EXISTE PAS en prod : le pipeline reçoit un `TtsProvider` par un `ProviderRegistry` ; en prod, `OpenAICompatibleTtsProvider` (`POST {baseUrl}/v1/audio/speech`, `response_format: wav`, via `EgressGuard.fetch`, `AbortSignal`, `health()` sur `GET /health` puis `/v1/audio/voices`) ; le narrateur reste `NoNarrator` dans ce slice (narration désactivée ; `OllamaNarrator` en phase 4). En tests, `FakeTtsProvider` injecté par une variable d'environnement `LLM_VOICE_TEST_FAKE_TTS=1` lue uniquement en mode développement/test (jamais en VSIX release : garde par `context.extensionMode`).
6. **Pipeline** (`src/pipeline/Pipeline.ts`) implémente `PipelineFacade` : source → `parseMarkdown` (ou texte brut en phrases pour non-Markdown) → `segment` selon le profil → `buildSession` → `PlaybackController` avec `WebviewAudioSink` (aligner `WebviewAudioSink` sur `AudioSink`) → `HighlightController.show` sur `onChunkChange` → status bar sur `onStateChange` → player `state` sur `onProgress`. Erreurs : provider indisponible → message avec « Retry / Open provider settings », jamais de crash (AC-16 partiel). Stop → highlight retiré, jobs annulés (AC-05). Pause → position conservée (AC-04).
7. **Verify Local Mode** : commande câblée sur `verifyLocalMode` avec les vraies entrées (URLs des settings, CSP du player, `package.json` deps), résultat dans un Quick Pick + badge `$(lock)` status bar.
8. **Tests d'intégration** (test-electron, xvfb, `LLM_VOICE_TEST_FAKE_TTS=1`) : AC-01 Speak Document démarre une session (état `playing` observable via une API de test exportée par `activate()` en mode test) ; AC-02/03 décoration posée sur la range du premier segment puis déplacée au `ended` du FakeAudioSink ou du webview (utiliser le FakeAudioSink en test si le webview ne charge pas d'audio sous xvfb : documenter) ; AC-04 pause conserve `currentChunkIndex` et la décoration ; AC-05 stop retire la décoration et `AbortSignal.aborted` sur le job en cours ; AC-06 Speak Selection ne lit que la sélection ; **invariant zéro autoplay** : test statique `test/unit/invariants/no-autoplay.test.ts` qui échoue si `src/claude/**` ou `src/inbox/**` importe `PlaybackController` ou appelle `start(` (grep des imports).
9. **Docs** : `README.md` section « Essayer en 2 minutes » (F5 dans VS Code, `LLM_VOICE_TEST_FAKE_TTS=1`, puis Chatterbox en phase 4) ; `CHANGELOG.md` Unreleased.

## Critères d'acceptation

- AC-01..06 verts en intégration sur ubuntu (xvfb) ; unit ≥ 80 % global.
- `npm run package` produit un VSIX installable : `code --install-extension llm-voice.vsix` puis `Speak Document` sur un .md sans serveur TTS affiche l'erreur propre « TTS unavailable » avec Retry (pas de crash).
- Aucun appel réseau hors loopback en test (EgressGuard en mode local, logger vérifié).
- CI 9/9 verte.
